## 性能预算的验收方法

TP21 在固定 Node/硬件、预热后各测 5 次取中位数；数据构造时间不计入解析时间，但端到端/API 单独计量。记录每次值和内存，不能只挑最快一次。

- 10k、20k、40k 唯一值单列：40k 中位耗时不超过 10k 的 6 倍，避免现有近平方增长；短任务计时噪声过大时扩大规模并记录同等比例。
- 第一阶段目标数据 100k×20、文件小于 20MB：完整解析/画像应在本地基准机 5 秒内，进程额外峰值内存目标不超过 512MB。此为拟定工程验收预算，不是对现有实现的性能承诺；调整必须有测量和评审记录。
- 同时请求轻量健康/只读接口，p95 相对空闲基线增加不超过 200ms。不能以解析总时间合格掩盖 API 长时间阻塞。
- 超过既有 50MB/100万行/200列限制明确拒绝。硬上限内不能 OOM 或卡死；边界测试在受控资源下执行，不在现用服务上压测。

若同步 API 仍无法达标，保持 R10 未完成并提交 G6 隔离执行设计；本次不会事先假定仅改算法必然满足预算。
