## 背景与结论

代码审查发现：预览与导出使用不同数据/绘图逻辑；编辑和复制可能丢失来源快照；审核可接受不完整输出或混合不同版本的图表与结论；部分数据解析和环比计算静默错误。现有离线和集成测试通过，不能覆盖这些缺陷。

保留 monorepo、模块化单体 API、Generation Worker、Render Worker、PostgreSQL 和私有对象存储。优先在既有模块中修复不变量；不整体重写，不增加微服务或消息中间件。

本轮 Outcome 是一份可评审、可按任务实施的修复规范。后续实施的主要 aggregate 为 Chart Artifact 及其 Chart Revision/Evidence Block；数据解析和变换按独立批次验证，为同一证据闭环提供正确输入。

## 用户场景

顾问在同一 Project 中导入表格，生成一个 Evidence Block，修改标题或图表逻辑，复制或回滚版本，最后由 Reviewer 审核并导出。整个过程中，用户看到的图形、发现文本、指标口径、来源、校验和固定 Revision 身份必须一致。后台失败、刷新和重复操作不能生成可批准的半成品。

## 分批交付与成功标准

1. A：相同固定输入下，前端与导出一致，F1/F2/F7/F8 回归通过。
2. B：生成、编辑、复制、回滚、历史审核和并发/故障恢复通过；新完成版本 100% 有完整来源、两层校验和固定输出清单。
3. C：性能预算有实测证据，相关门禁为零失败，完整闭环回归通过。结构整理只在行为测试保护下进行。

每批是独立可验收的垂直结果，不以“接口返回成功”“PNG 有文件签名”或“类型检查通过”替代业务验收。首期产品整体缺口仍另行追踪，完成修复不等于第一阶段全部完成。

## 审核重点与依赖

待审核方案：以冻结 Vega-Lite 为图形语义来源；一个 Revision 对应一个不可变 Evidence 内容；修订提交受 Job/Artifact 事务控制；复制/回滚改为异步完成。取舍见 [ADR-0032](../../adr/0032-canonical-chart-rendering.md)、[ADR-0033](../../adr/0033-atomic-revision-evidence-publication.md)，均为 Proposed。

兼容性实验必须在后续实施授权后运行；本轮没有安装 Vega 依赖、验证浏览器/服务端运行时或承诺具体包版本。历史混合证据不能可靠回填时保留并标注未验证，不能猜测。未来 API 变化必须同步 contracts、OpenAPI、API Console 和 Web。
