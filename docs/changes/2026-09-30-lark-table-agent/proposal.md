## 授权与范围

用户明确要求系统用 lark-cli 读取表格，由 Agent 管理工具，并完成配置研究和项目集成。本次据此实施上传 → 异步表格 Agent → 不可变 Snapshot → 现有图表生成链路。用户没有要求部署生产、推送代码或覆盖飞书已有文件。

## 问题与目标

旧上传接口把原始文件完整读入 API 内存，本地解析器默认取第一个工作表、猜表头；图表编译器还可能忽略模型选定的列。这些行为使字段误识别无法追溯。目标是用固定版本的官方 CLI 导入新飞书表格、读取真实结构；模型仅接收有界的工具观察，选择工作表和数据区域，程序负责完整性检查、计算和保存。

## 验收要求

1. 开启飞书接入后，CSV/XLSX 上传与新版本上传均不调用本地 Excel 解析器；API 返回异步处理状态。
2. 模型通过受限的 inspect_sheet / select_table / clarify 动作管理工具，不接收文件 bytes、账号凭据或整张大表。
3. 多 Sheet、标题行、重复列、空白列、截断、版本变化和授权失效有明确处理；不能静默成功。
4. 授权固定到明确的 LangReport 用户与 Workspace，以及专用 CLI profile 和飞书用户；不能退回默认账号。
5. 保留源文件、CLI 版本、来源表格与区域、列位置、工具调用和模型用量记录。历史 Snapshot 不跟随飞书实时变化。
6. 离线测试不调用飞书/模型；提供 Windows 配置命令和实际授权后的验收方法。

## 边界

本轮优先单用户专用连接；多用户 OAuth 自助接入需独立设计。JSON/粘贴数据保持既有方式。飞书导入会创建一个新在线表格；不自动覆盖、追加或删除已有云文件。超出有界读取能力时明确失败，不能宣传无限规模流式 Excel。真实飞书验收依赖用户浏览器授权。
