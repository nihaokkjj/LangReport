## 背景

LangReport 已有 Conversation Memory 快照、Project/Workspace Memory、候选确认/拒绝、冲突检测、软删除，以及 Generation Job/Chart Revision 的记忆上下文投影。当前实现集中在 `packages/memory`，既有边界由 ADR 0004 定义。

现状仍有几处缺口：Conversation 没有显式归档状态；短期摘要只是最近消息的简单串接；记忆提取在用户消息写入后触发；检索按更新时间和关键词过滤；没有私有用户偏好作用域；长工具/模型循环没有统一的逐次调用压缩门。

## 要解决的问题

1. 长对话不能稳定保留已确认目标、事实、决策、未决问题和约束。
2. Task、Conversation、Project 与个人偏好的作用域和结束条件不清楚。
3. 模型推断、用户确认事实、当前请求和个人偏好可能混入同一个提示或持久化快照。
4. Reviewer/项目成员可能通过 Job、Revision、记忆 API、审计记录或日志看到个人偏好元数据。
5. 长期记忆的冲突、检索预算、低价值衰减、用户修改/删除和摘要并发更新缺少可验证规则。

## 目标用户与场景

- 咨询顾问：在一个 Conversation 中持续澄清问题；在不同 Project 中沿用自己的语言、语气、详略和交互偏好。
- 项目成员：在同一 Project 中复用已确认的指标口径、术语、数据定义和业务规则。
- Reviewer：检查 Project 事实及其来源；不能查看生成者的用户偏好内容或任何偏好标识。

## 需求范围

### 本变更的目标范围

- R1：定义 Task、Conversation（会话层）、Project、User Preference 四类活动记忆，并定义 Workspace Memory 的未来兼容边界。
- R2：分开定义指令优先级和事实背景优先级；当前明确请求只覆盖本次执行，不静默改写长期记忆。
- R3：定义 Task/Conversation 结束语义、Project/偏好的持久语义、确认时间、冲突待更新和低价值衰减。
- R4：每次持久化的面向用户助手回复后异步生成记忆候选；纯内部/工具调用不触发；候选证据只能来自用户对话陈述。
- R5：用户明确要求记住的内容直接成为已确认记忆；模型提取候选必须接受、编辑或拒绝后才能成为长期记忆。
- R6：Task 是跨澄清的逻辑分析任务；每个新 Generation Cycle 重新检索已确认记忆并固定消息来源及摘要边界。澄清创建新 Cycle、保留 Task；同一 Cycle 的执行重试复用固定上下文，不读取后续消息。用户删除是冻结规则的例外：删除成功后，后续模型调用不再注入已删除记忆，包括当前运行中的 Cycle；不追溯撤回已发出的调用和已生成结果。
- R7：每次模型调用前按配置检查上下文压缩；多阈值为 OR；压缩失败时保留原文并禁止下游模型调用。
- R8：提供可解释的候选确认、私有偏好管理和私有使用记录；用户可查看、修改、删除已确认记忆。
- R9：Reviewer/项目成员及项目可见 Job、Revision、API、审计和日志不暴露个人偏好内容、键、哈希、ID 或使用标记。
- R10：首期检索采用确定性范围/类型/键/关键词相关性和上下文预算；记录命中、冲突、排除及版本依据。

### 后续范围

- Workspace Memory 的启用、UI、自动读写和 API 读写；首期只保留已有行，不查询、不修改。
- 向量或混合语义检索、自动批准、长期行为画像、记忆图谱、外部向量数据库。
- 跨认证用户同步、团队共享个人偏好和组织策略。
- 自动衰减调优后置；压缩阈值和队列参数仍在首期 B3/C1 通过可配置策略与固定样例确定，不是新的用户产品决策。

## 已确认的治理补充

- 个人偏好删除清除记忆存储内当前/历史正文和派生副本，保留 owner-only 无正文删除记录；Project 删除后历史仅授权审计可见。
- 原始对话、报告独立留存；删除必须防止旧来源、延迟队列、缓存和摘要重新注入，不承诺撤回已发出的调用。
- 稳定逻辑 ID 与不可变版本；current、as-of、actual-used 分开。候选冲突不废弃已确认事实，确认冲突仅阻断相关分析。
- 优先级不能覆盖权限、Snapshot 事实、Metric Definition 确认或 Approved Revision 不可变。
- 会话归档前必须结束或显式取消未完成 Task；不会静默取消。

## 三批交付

A：版本、私有隔离、人工管理与删除闭环；B：Task/Cycle、固定来源、逐调用压缩与归档；C：异步候选、门控、冲突与完整验收。依赖和退出门见 [task.md](task.md)。

## 明确不做

- 不把 Conversation 摘要或模型推断直接升级为 Project Memory。
- 不从 CSV/XLSX/JSON 原始数据行或样例值抽取候选；不保存密钥、凭证、隐藏推理或任意脚本。
- 不把 User Preference Memory 变成 Project/Workspace 事实，也不把 Project 规则复制为个人偏好。
- 不把归档对话自动注入为历史记忆；原始对话仍可搜索。
- 不改变第一阶段单 Project、单 Data Snapshot、单 Analysis Brief、单 Evidence Block 的产品边界。
- 本轮仅实施 A 批；不运行生产迁移，不使用真实用户数据或真实模型验证隐私与并发安全。B/C 后续任务仍需独立授权。

## 成功指标

- 逐次模型调用均能证明阈值检查正确；达到任一配置阈值即压缩，压缩失败不调用下游模型且原始消息完整。
- Session 摘要版本、覆盖水位和原始消息可追溯；归档 Conversation 不再进入活动上下文。
- inferred/proposed 候选永远不进入确认记忆检索；直接明确的“记住”动作有来源和确认时间。
- 同一 Cycle 的执行重试保持冻结来源和版本；澄清创建新 Cycle 并重新选择，Task 连续。Task 成功、最终失败或取消后停止 Task Memory 注入；逐调用排除已删除记忆及派生副本。
- 其他用户和项目成员无法从项目/工作区 API、Job、Revision、审计、日志或 API Console 示例读取个人偏好元数据。
- Workspace 记忆行在首期不被读取、写入或删除。
- 离线测试覆盖优先级、冲突、候选生命周期、生命周期终点、预算、并发、隐私和 API Console 契约。

## 假设、依赖与风险

- 复用已交付的 users 表和认证 userId；A1 核对实际主键/关系，不新增账户体系或推测主键类型。
- 记忆修改采用版本和乐观并发；用户确认时间与来源可审计，但不记录隐藏推理。
- 相关模块包括 `packages/memory`、`packages/contracts`、`packages/db`、`packages/domain`、`packages/generation`、`packages/model-gateway`、API、Generation Worker、Web/API Console 和 Chart Revision 快照。
- 最大风险是私有偏好通过共享 Job JSON、Revision、幂等 fingerprint、调试日志或错误详情泄露；design.md 将偏好运行时上下文和项目可见快照物理分离。
- 当前工作树中已有的登录网关、工作台主题及记忆术语修改均需保留；本变更只处理记忆相关文档。
- DeerFlow 只作为异步处理、队列合并、结构化提议和候选信号设计参考；LangReport 继续执行“推断需确认”的规则。
