# ADR-0027：由数据库用户表管理登录身份

- 状态：Accepted
- 日期：2026-09-26
- 变更：CHG-2026-09-26-database-user-accounts

## 背景

当前登录网关从部署环境变量读取单一 username、scrypt password hash 和 user ID。用户需要多个可独立停用、重置或自行修改密码的账号，并要求账号管理限定在服务器 CLI。

项目当前通过 Workspace Member 和 Project Member 关系按 user ID 隔离数据；登录 session 是最长 7 天的无状态 HS256 JWT。首个数据库身份必须接收已有单用户部署的成员关联，已签发 JWT 则按原 exp 保留。

## 决策提案

1. 新增 users 表作为数据库登录身份和密码 hash 的权威来源；不新增应用管理员 role。
2. 密码仍使用现有 scrypt 编码格式；账号创建和重置使用部署注入的共享随机秘密，用户也可自行修改。
3. 应用仅在 users 表为空时从显式配置 bootstrap 首个普通用户；重复启动不能覆盖用户状态或密码。
4. 账号创建、停用、启用和重置仅由服务器 CLI 执行；用户自助改密通过登录后的 account 页面。
5. 软停用并保留 Workspace/Project 数据；无邮件恢复、账号操作审计、服务端 Session 撤销或 MFA。
6. 停用、管理员重置密码或用户自助改密后，所有现存 JWT 均保留到各自原 exp，最多 7 天。迁移前 subject 通过有到期时间的临时 alias 映射到 bootstrap 用户，最多 7 天。
7. 应用删除登录失败计数；生产登录入口必须由 Nginx/WAF 限速，API 仅在内部网络开放。

## 考虑过的方案

- 保持环境变量单账号：无新数据模型，但无法满足独立账号生命周期与自助改密。
- 数据库 users + 现有 JWT/Cookie：可复用目前授权、Workspace 和部署边界，迁移工作可控。
- 外部 IdP：可提供更丰富的身份与恢复能力，但增加外部系统、部署和账户同步范围；当前不需要。

## 后果

正面结果：

- 每个咨询用户拥有独立登录身份，现有 Workspace/Project 授权逻辑仍可按 user ID 工作。
- CLI 运维权限与应用用户角色分离；没有全局管理员页面或额外的数据访问权限。
- 用户可更新自己的密码，停用账号保留业务数据。

需要接受的风险：

- 6 字符的自设密码低于单因素密码通行基线；入口限速必须由 Nginx/WAF 保证。
- 多个未自行修改的账号可能共享同一初始/重置密码。
- 账号停用、密码重置或用户自助改密不会立即撤销最多 7 天的既有 JWT。
- 临时旧身份 alias 增加认证解析路径，必须按原始 exp 停止生效。
- API 直接暴露公网会绕过入口限速；生产网络拓扑必须阻断旁路。
- 本 ADR 已随 CHG-2026-09-26-database-user-accounts 完整 SDD 获用户批准。

## 验收标准

- 每个登录账号均对应唯一 users.id 和唯一规范化 username。
- 明文密码不进入数据库、CLI 输出或日志；只存带随机 salt 的 scrypt hash。
- 用户状态、密码策略、会话保留和旧 subject 迁移行为与批准后的 SDD 一致。
- 生产入口限速和 API 网络隔离有可复现验证。
