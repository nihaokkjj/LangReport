# ADR-0030：Web 通用组件采用 Material UI

- 状态：Accepted（2026-09-29 用户回复“审批通过”）
- 日期：2026-09-29
- 变更：`CHG-2026-09-29-mui-web-ui`

## 背景

LangReport Web 已有 `DESIGN.md` 和暖色 CSS 令牌，但工作台及工具页面独立实现按钮、表单、菜单和弹层。相同操作的尺寸、圆角、颜色和反馈不一致。用户明确选择带样式组件库作为全站统一方案。

## 决策提案

1. Web 通用可见控件采用稳定版 Material UI Core v9；MUI 主题映射现有 `DESIGN.md`，统一字体、色彩、间距、圆角和状态。
2. 使用 MUI 官方 Next.js App Router 样式缓存集成；与现有 CSS Modules 共存时验证 CSS layer、SSR 和客户端导航。
3. 页面和 feature 仍拥有 Project、Conversation、Evidence、Review 等业务组合与状态；MUI 控件不接管 API、权限或领域事实。
4. Evidence 画布、图表预览与服务端导出继续走现有专用实现；自定义双抽屉布局继续满足 ADR-0023 的并行开启、右侧调宽和原位 Snapshot 预览要求。

## 考虑过的方案

| 方案                      | 优点                                       | 主要代价                              | 结论             |
| ------------------------- | ------------------------------------------ | ------------------------------------- | ---------------- |
| 继续自研通用控件          | 无新依赖，视觉可控                         | 页面实现分散，交互与可访问性维护重复  | 不采用           |
| 无样式基础库 + 自有控件层 | 外观自由，交互基础成熟                     | 仍需维护整套带样式控件                | 用户未选择       |
| Material UI 全站通用组件  | 主题、基础控件与交互状态集中，覆盖现有页面 | 依赖与 SSR 集成成本，需系统性迁移 CSS | 采用，设计已批准 |

## 后果与验证门

- 统一性来自同一主题和实际替换，单纯安装依赖不满足本决策。
- MUI 默认视觉经主题配置贴合 `DESIGN.md`；图表 `Visual Template` 仍独立、版本化且可追溯。
- 首轮验证需证明 Next.js 16 / React 19 的安装、SSR 样式注入、CSS 覆盖顺序和四视口交互可用；若官方包导出或样式机制不满足条件，停在技术门并修订本 ADR 与设计，不静默改用另一库。
- 不引入 MUI X 商用包；如未来需要，另行评估许可和范围。
